Como eu fiz essa loja

Desafio Bootcamp AI/R — Trilha Commerce, agosto/2026

O que é isso

Rabo Aceso é uma mini-loja de artigos pra pets, construída como site estático — sem back-end, sem banco de dados. Tudo o que existe é HTML, CSS, JavaScript e um arquivo de dados.

Arquitetura de arquivos

  • index.html — estrutura da vitrine: cabeçalho, hero e os contêineres vazios que o JS preenche.
  • products.json — o catálogo. Cada produto é um objeto com id, nome, categoria, preço, ícone e descrição.
  • script.js — busca o JSON com fetch, filtra por categoria/texto e desenha os cards no DOM.
  • styles.css — identidade visual: cores, tipografia, grid responsivo.
  • como-fiz.html — esta página.

Por que separar o catálogo do front (headless commerce)

Nenhum produto está escrito dentro do HTML. A vitrine só sabe pedir "me dá a lista de produtos" e desenhar o que receber — ela não sabe, de antemão, quantos produtos existem ou quais são. Isso é o miolo do conceito de headless commerce: separar onde os dados moram (o "corpo", que numa loja real seria uma API/CMS) de como eles aparecem (a "cabeça", aqui o HTML/CSS/JS). Trocar o catálogo inteiro nunca exige tocar em uma linha de JavaScript.

Se fosse pra AWS

Hoje o fetch busca um arquivo estático hospedado ao lado do site. Numa versão AWS, o navegador do cliente bateria numa CDN (CloudFront) que serve os arquivos estáticos direto de um bucket S3 — e o products.json viraria uma chamada de API (API Gateway + Lambda, lendo de um banco tipo DynamoDB) em vez de um arquivo fixo. O cache do CloudFront é o que evita que 10 mil acessos simultâneos cheguem todos na origem: a maioria é respondida direto na borda, perto do usuário.

Bônus: onde entraria um BFF

Se essa loja ganhasse um app mobile, um Backend for Frontend (BFF) entraria entre o app e as APIs internas — uma camada só pra moldar e agregar dados especificamente pro formato que o app mobile precisa, diferente do que o site web consome. Evita que o cliente mobile tenha que fazer várias chamadas separadas ou lidar com payloads pensados pra web.

Stack

  • HTML5 + CSS puro (sem framework)
  • JavaScript vanilla (fetch, sem bibliotecas)
  • Hospedagem: GitHub Pages (gratuito)
